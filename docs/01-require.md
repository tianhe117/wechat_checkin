# 需求说明

## 1. 项目目标与范围

通过手机网页管理 Android 手机上的企业微信定时操作，支持上班、下班计划、手动执行、截图核对和消息通知。关闭网页后，后台计划继续运行。

系统面向个人使用，由管理端统一管理一台目标手机，控制端通过 ADB 执行手机操作。系统以执行步骤和截图记录操作结果，实际打卡结果由用户查看截图确认。

## 2. 运行前提

- Android 手机通过 USB 连接 Windows 主机，已启用并授权 ADB 调试，解除锁屏密码，安装目标应用。
- Windows 主机运行控制端；Linux 主机通过 Docker 运行管理端。
- 管理端能够通过局域网访问控制端；浏览器访问管理端，Bark 通知按需配置。
- 两端持续运行，手机保持连接；所有业务日期和计划时间采用北京时间（UTC+8）。

## 3. 功能需求

| 功能 | 要求 |
| --- | --- |
| 手机访问 | 页面适配手机 |
| 登录与密码 | 登录后访问管理页面、记录和截图；修改密码需校验当前密码，修改后其他会话失效 |
| 概览 | 展示控制端与手机状态、设备信息、当天计划、下次计划、暂停状态和最近执行结果 |
| 自动计划 | 设置每周执行日、上班和下班场次的启用状态及时间窗口，在窗口内随机安排执行时刻 |
| 日期覆盖 | 单日或日期范围设置为默认、打卡、请假；默认沿用周规则，打卡使用启用的场次，请假跳过自动执行 |
| 暂停与恢复 | 暂停新自动任务的派发，手动操作仍可使用；恢复后等待未来有效计划 |
| 手动执行 | 随时发起完整手机操作，独立记录，不占用或替代自动计划 |
| 当前截图 | 亮屏解锁后采集当前界面，保留所在应用及截图后的亮屏状态 |
| 设备测试 | 亮屏、解锁、返回桌面并截图，独立于目标应用配置 |
| 执行记录 | 按日期分页查看触发方式、计划与实际时间、步骤、状态、错误和截图，支持查看详情及再次执行 |
| 连接配置 | 设置控制端地址、API key 和可选设备序列号；序列号可直接填写或从设备列表选择 |
| 应用配置 | 设置可选应用包名与等待时间；包名留空时使用控制端默认应用 |
| 设备监测 | 区分控制端不可达、手机离线和未授权等情况，状态变化时通知，状态不变时不重复提醒 |
| Bark 通知 | 支持配置、测试和重发；通知执行完成、失败、错过及结果未知等情况，配置公网访问地址后可附记录链接及截图 |

## 4. 手机操作要求

完整执行流程为：

亮屏 → 解锁并返回桌面 → 关闭目标应用 → 启动目标应用 → 等待 → 截图 → 返回桌面 → 关闭目标应用 → 锁屏。

每次执行固定目标设备。应用启动后等待指定秒数，再采集截图；完整流程及收尾均成功时记为“操作完成”。中途失败后尽力完成返回桌面、关闭应用和锁屏，记录主错误、收尾错误及已有截图。无法确定最终结果时记为“结果未知”。

独立截图和设备测试按各自流程执行，不启动或关闭目标应用。

## 5. 业务规则

1. **计划持久化**：同一天、同一场次的随机计划保存到数据库，刷新页面或重启服务不重新随机。窗口需为等待和手机操作预留时间。
2. **规则变更**：修改时间窗口、场次启用状态或等待时间后，重新评估受影响场次；修改周规则或日期覆盖后，取消不再适用的待执行计划。历史记录保留，明确修改规则后可能产生当天的新计划。
3. **派发约束**：手动任务优先于待派发自动任务，正在执行的操作持续完成。自动任务超过计划时刻 5 秒、手机忙、暂停或条件失效时记录为错过，不自动补跑。
4. **避免重复**：一次逻辑操作使用固定请求编号，先保存任务再派发。重复点击合并同类在途手动任务；网络中断或服务重启后查询原请求。
5. **人工再次执行**：失败、错过和结果未知均保留原记录；用户明确再次执行时创建新操作及新请求编号。
6. **结果留存**：管理端长期保存业务记录和截图；控制端短期保存完整结果，并持续保留请求去重记录。
7. **通知独立**：通知发送结果单独记录，重发通知只发送消息，不触发手机操作。

## 6. 访问与凭据

管理页面、业务记录和截图要求登录，修改操作校验 CSRF。Bark 附图使用限于单条记录、24 小时有效的签名链接，允许客户端免登录下载。控制端所有 API 使用 Bearer API key 认证，仅供管理端调用。控制端与 Bark 密钥保存在服务端，页面不回显；留空保存时保持原值。
