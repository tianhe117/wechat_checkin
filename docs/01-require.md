# 需求说明

## 1. 项目目标与范围

通过手机网页管理 Android 手机上的企业微信定时操作，支持上班、下班计划、手动执行、截图核对和消息通知。关闭网页后，后台计划继续运行。

系统面向个人使用，由管理端统一管理一台目标手机，控制端通过 ADB 执行手机操作。系统以执行步骤和截图记录操作结果，实际打卡结果由用户查看截图确认。

## 2. 运行前提

- Android 手机通过 USB 连接 Windows 主机，已启用并授权 ADB 调试，解除锁屏密码，安装目标应用。
- Windows 主机运行控制端；Linux 主机通过 Docker 运行管理端。
- 管理端能够通过局域网访问控制端；浏览器访问管理端，Bark 通知按需配置。
- 两端持续运行，手机保持连接；所有业务日期和计划时间采用北京时间（UTC+8）。

## 3. 功能需求

| 功能 | 要求 |
| --- | --- |
| 手机访问 | 页面适配手机 |
| 登录与密码 | 登录后访问管理页面、记录和截图；修改密码需校验当前密码，修改后其他会话失效 |
| 概览 | 展示控制端与手机状态、设备信息、当天计划、下次计划、暂停状态和最近执行结果 |
| 打卡管理 | 自动计划、日期调整、暂停恢复及手动打卡，见第 4 章 |
| 当前截图 | 亮屏解锁后采集当前界面，保存截图后熄屏 |
| 设备测试 | 亮屏、解锁、返回桌面并截图，独立于目标应用配置 |
| 执行记录 | 按日期分页查看触发方式、计划与实际时间、步骤、状态、错误和截图，支持查看详情及再次执行 |
| 连接配置 | 设置控制端地址、API key 和可选设备序列号；序列号可直接填写或从设备列表选择 |
| 应用配置 | 设置可选应用包名与等待时间；包名留空时使用控制端默认应用 |
| 设备监测 | 区分控制端不可达、手机离线和未授权等情况，状态变化时通知，状态不变时不重复提醒 |
| Bark 通知 | 支持配置、测试和重发；通知执行完成、失败、错过及结果未知等情况，配置公网访问地址后可附截图，不附详情链接 |

## 4. 打卡需求

### 4.1 计划配置

上班、下班为两个独立场次，时间均指同一天内的开始至结束时间窗口，在有效窗口内随机执行一次。配置按以下三层生效，具体日期优先于星期配置，星期配置优先于默认配置。

| 层级 | 要求 |
| --- | --- |
| 默认配置 | 从周一至周日选择工作日，分别设置上班、下班场次的启用状态和默认时间窗口；非工作日默认不打卡 |
| 星期配置 | 可为周一至周五分别自定义上班、下班时间窗口；未自定义的场次沿用默认窗口；此层不改变工作日选择及场次启用状态 |
| 日期配置 | 可将今天及未来日期设为默认、打卡或请假，按下述规则执行 |

### 4.2 日期状态与日历

计划日历仅使用“默认 / 打卡 / 请假”三种状态和样式。

| 状态 | 要求 |
| --- | --- |
| 默认 | 按默认工作日、场次启用状态及星期时间配置执行；恢复默认并保存时清除当天自定义配置 |
| 打卡 | 不受工作日选择限制，使用当天独立的场次开关和时间窗口，可上下班都打、仅打上班、仅打下班或两场都关闭；日历均显示打卡样式 |
| 请假 | 当天上班、下班均不自动打卡 |

当天首次设置为打卡时，上下班开关取默认配置，时间窗口优先取对应星期配置，没有则取默认窗口，之后可完全自定义。保存后固定为当天配置，不随默认或星期配置变化；再次编辑时回显已保存值，具体安排在日期编辑页查看。

支持按日期范围批量设置状态：默认清除单日配置，请假关闭全天自动打卡，打卡按范围内每个日期的默认及星期配置分别初始化并保存。批量保存替换范围内已有的单日配置，保存前须明确提示；批量不设置自定义时间。

### 4.3 计划生成与变更

1. **持久化**：随机执行时刻保存后，刷新页面、重启服务或保存未变化的有效配置不重新随机。启用窗口须为等待和手机操作预留时间。
2. **变更范围**：仅更新有效配置发生变化的日期和场次；调整等待时间时重新评估受影响计划。取消不再适用的待执行或尚未开始派发的排队任务，必要时按新配置生成计划，保留原记录。
3. **当天调整**：新计划仅在剩余有效窗口内生成，已无可用时间则记为错过。因规则变更取消的场次可重新启用；已开始执行、已完成、失败、结果未知或已错过的场次，不因修改配置自动再次执行。
4. **暂停与恢复**：暂停新自动任务的派发，不影响手动操作及已开始的任务；恢复后等待未来有效计划，不补跑已错过计划。
5. **派发约束**：手动任务优先于待派发自动任务，正在执行的操作持续完成。自动任务超过计划时刻 5 秒、手机忙、暂停或条件失效时记录为错过，不自动补跑。

### 4.4 手动打卡

手动发起完整手机操作，独立记录，不占用或替代自动计划，不受日期状态限制。每次执行（含再次执行）弹窗提示 6 个不重复数字，须在随机九宫格中依次点选，再点“确认打卡”才执行；点错重选，取消不执行。再次执行创建新操作及新请求编号，保留原记录。

## 5. 手机操作要求

完整执行流程为：

亮屏 → 解锁并返回桌面 → 关闭目标应用 → 启动目标应用 → 等待 → 截图 → 返回桌面 → 关闭目标应用 → 锁屏。

每次执行固定目标设备。应用启动后等待指定秒数，再采集截图；完整流程及收尾均成功时记为“操作完成”。中途失败后尽力完成返回桌面、关闭应用和锁屏，记录主错误、收尾错误及已有截图。无法确定最终结果时记为“结果未知”。

独立截图和设备测试按各自流程执行，不启动或关闭目标应用。

## 6. 业务规则

1. **避免重复**：一次逻辑操作使用固定请求编号，先保存任务再派发。重复点击合并同类在途手动任务；网络中断或服务重启后查询原请求。
2. **结果留存**：管理端长期保存业务记录和截图；控制端短期保存完整结果，并持续保留请求去重记录。
3. **通知独立**：通知发送结果单独记录，重发通知只发送消息，不触发手机操作。

## 7. 访问与凭据

管理页面、业务记录和截图要求登录，修改操作校验 CSRF。Bark 附图使用限于单条记录、24 小时有效的签名链接，允许客户端免登录下载。控制端所有 API 使用 Bearer API key 认证，仅供管理端调用。控制端与 Bark 密钥保存在服务端，页面不回显；留空保存时保持原值。
